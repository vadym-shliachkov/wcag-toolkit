# 2.4.7 Focus Visible

WCAG 2.2 · Level **AA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

The interface is keyboard operable.

## What is required

When operated by keyboard, a focus indicator is visible.

## How to test

1. Move through every element with the keyboard.
2. Check focus in all themes, backgrounds and states.

**Expected result:** When operated by keyboard, a focus indicator is visible. All applicable states and normative exceptions have been checked.

**Fails when:** The outline is removed and there is no other visible indicator.

## How to fix

Keep the default indicator or add a robust :focus-visible style.

## Example

**Before:** On Tab, the button looks the same as before it received focus.

**After:** A noticeable outline shows the current button.

## Exceptions and false positives

Do not automatically carry the numeric area requirements of 2.4.13 over to this AA criterion; also check contrast under 1.4.11 where applicable.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. For this criterion it is especially important to compare the programmatic data with the actual presentation.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 2.4.7, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Move through every element with the keyboard; check focus in all themes, backgrounds and states.
