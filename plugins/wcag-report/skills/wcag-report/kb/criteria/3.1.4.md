# 3.1.4 Abbreviations

WCAG 2.2 · Level **AAA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

Abbreviations; AAA.

## What is required

Provide a mechanism for identifying the expanded form or the meaning.

## How to test

1. Find abbreviations.
2. Check access to the expanded form, including with keyboard and touch input.

**Expected result:** Provide a mechanism for identifying the expanded form or the meaning. All applicable states and normative exceptions have been checked.

**Fails when:** An abbreviation matters for an action but is not explained anywhere.

## How to fix

Expand it on first use or provide an accessible glossary.

## Example

**Before:** A form asks for the "OSID" without explanation.

**After:** Next to it, "observation station identifier" is explained.

## Exceptions and false positives

A title attribute alone cannot be assumed to be a universally accessible mechanism; check real access to the definition.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 3.1.4, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Find abbreviations; check access to the expanded form, including with keyboard and touch input.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
