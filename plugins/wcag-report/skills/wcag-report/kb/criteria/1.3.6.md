# 1.3.6 Identify Purpose

WCAG 2.2 · Level **AAA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

Interface components, icons and regions in markup; AAA.

## What is required

The purpose must be programmatically determinable so that the presentation can be adapted.

## How to test

1. Check the semantics of regions and common components.
2. Compare them with the actual purpose.
3. Assess support for the chosen mechanism.

**Expected result:** The purpose must be programmatically determinable so that the presentation can be adapted. All applicable states and normative exceptions have been checked.

**Fails when:** Repeated regions and buttons do not expose a programmatically determinable purpose.

## How to fix

Apply suitable semantic elements and supported mechanisms for identifying purpose.

## Example

**Before:** The main content and the navigation consist of unnamed containers.

**After:** The main and nav elements convey the purpose of the regions.

## Exceptions and false positives

Do not reduce the criterion to one mandatory attribute; a good accessible name does not always fully convey a component's purpose.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 1.3.6, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Check the semantics of regions and common components; compare them with the actual purpose; assess support for the chosen mechanism.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
