# 1.2.6 Sign Language (Prerecorded)

WCAG 2.2 · Level **AAA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

Prerecorded audio in synchronized media; AAA profile.

## What is required

Provide sign language interpretation.

## How to test

1. Find the version with interpretation.
2. Check completeness, synchronization and accessible switching.

**Expected result:** Provide sign language interpretation. All applicable states and normative exceptions have been checked.

**Fails when:** In a required AAA profile, a recorded lecture has no sign language interpretation.

## How to fix

Add synchronized sign language interpretation and clear access to that version.

## Example

**Before:** A recorded briefing comes only with sound and captions.

**After:** A version with sign language interpretation is available.

## Exceptions and false positives

Do not require this criterion for a Level A or AA conclusion; captions are not equivalent to sign language interpretation.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 1.2.6, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Find the version with interpretation; check completeness, synchronization and accessible switching.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
