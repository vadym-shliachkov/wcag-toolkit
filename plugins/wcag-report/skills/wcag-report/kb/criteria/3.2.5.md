# 3.2.5 Change on Request

WCAG 2.2 · Level **AAA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

Any change of context; AAA.

## What is required

Changes of context happen on user request, or a mechanism is available to turn them off.

## How to test

1. Observe timers and input.
2. Check control over automatic transitions.

**Expected result:** Changes of context happen on user request, or a mechanism is available to turn them off. All applicable states and normative exceptions have been checked.

**Fails when:** The page moves the user to another section on its own, with no way to stop it.

## How to fix

Remove the automatic transition or provide a reliable way to turn it off.

## Example

**Before:** While the user reads a card, the next card opens after 15 seconds.

**After:** The transition is made with a "Next" button.

## Exceptions and false positives

A warning that is sufficient in some cases for 3.2.2 does not always satisfy this stricter AAA criterion.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 3.2.5, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Observe timers and input; check control over automatic transitions.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
