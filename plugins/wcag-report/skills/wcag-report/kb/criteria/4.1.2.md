# 4.1.2 Name, Role, Value

WCAG 2.2 · Level **A**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

All user interface components, including custom widgets.

## What is required

The name and role can be programmatically determined; states, properties and values that can be set by the user can be programmatically set, and changes are available to assistive technologies.

## How to test

1. Compare the actual function with the computed role and name.
2. Change the state.
3. Check the accessibility tree and the available actions.

**Expected result:** The name and role can be programmatically determined; states, properties and values that can be set by the user can be programmatically set, and changes are available to assistive technologies. All applicable states and normative exceptions have been checked.

**Fails when:** A toggle changes visually, but its state is not programmatically available.

## How to fix

Use a native element, or complete and correct semantics with property updates.

## Example

**Before:** A mode toggle is an unnamed div that changes color.

**After:** A checkbox with a label conveys its name and checked state.

## Exceptions and false positives

The presence of an ARIA attribute does not confirm a correct implementation. Invalid HTML on its own is not a substitute for evidence of a name, role or state problem.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. For this criterion it is especially important to compare the programmatic data with the actual presentation.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 4.1.2, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Compare the actual function with the computed role and name; change the state; check the accessibility tree and the available actions.
