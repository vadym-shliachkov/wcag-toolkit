# 2.4.8 Location

WCAG 2.2 · Level **AAA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

A set of web pages; AAA.

## What is required

Provide information about the user's location within the set.

## How to test

1. Check breadcrumbs, highlighting of the current item and other location information.

**Expected result:** Provide information about the user's location within the set. All applicable states and normative exceptions have been checked.

**Fails when:** In a deep set of sections, there is no way to tell the current section.

## How to fix

Add a clear indication of location.

## Example

**Before:** A nested instructions page does not show which section it belongs to.

**After:** The path "Home → For readers → Renewal" shows the location.

## Exceptions and false positives

Breadcrumbs specifically are not required; another clear mechanism is enough.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 2.4.8, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Check breadcrumbs, highlighting of the current item and other location information.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
