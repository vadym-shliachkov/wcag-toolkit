# 2.5.5 Target Size (Enhanced)

WCAG 2.2 · Level **AAA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

Pointer input targets; AAA.

## What is required

The size is at least 44×44 CSS px, except for the normative exceptions.

## How to test

1. Measure the interactive area, not just the icon.
2. Check for an equivalent target and the other exceptions.

**Expected result:** The size is at least 44×44 CSS px, except for the normative exceptions. All applicable states and normative exceptions have been checked.

**Fails when:** A standalone button has a 20×20 area and no exception applies.

## How to fix

Enlarge the area to 44×44 CSS px.

## Example

**Before:** A paging button measures 22×22.

**After:** Its interactive area is 46×46.

## Exceptions and false positives

Exceptions: equivalent target, inline text, unmodified user agent control, essential presentation. The 24px spacing rule belongs to 2.5.8, not to this criterion. The equivalent target must be on the same page and be at least 44×44 CSS px.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. For this criterion it is especially important to compare the programmatic data with the actual presentation.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 2.5.5, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Measure the interactive area, not just the icon; check for an equivalent target and the other exceptions.
