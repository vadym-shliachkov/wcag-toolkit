# 2.4.10 Section Headings

WCAG 2.2 · Level **AAA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

Content is organized into sections; AAA.

## What is required

Use section headings to organize the content.

## How to test

1. Identify the meaningful sections.
2. Check whether they are marked with headings.

**Expected result:** Use section headings to organize the content. All applicable states and normative exceptions have been checked.

**Fails when:** Long instructions consist of different sections with no headings.

## How to fix

Add meaningful headings and a semantic hierarchy.

## Example

**Before:** The rules for registration, renewal and return are merged into one long text.

**After:** Each section has a heading.

## Exceptions and false positives

Not every short text or interface block has to become a section; apply this to the real structure of the content.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 2.4.10, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Identify the meaningful sections; check whether they are marked with headings.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
