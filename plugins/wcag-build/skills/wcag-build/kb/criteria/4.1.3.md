# 4.1.3 Status Messages

WCAG 2.2 · Level **AA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

A status message appears without a change of context.

## What is required

Programmatically determine the role/properties so that assistive technologies can present the message without it receiving focus.

## How to test

1. Trigger a search result, a save, an error and progress.
2. Determine whether the message is a status message.
3. Check that it is announced without moving focus.

**Expected result:** Programmatically determine the role/properties so that assistive technologies can present the message without it receiving focus. All applicable states and normative exceptions have been checked.

**Fails when:** The text "Saved" appears visually, but the status is not programmatically determined.

## How to fix

Use an appropriate role="status", alert or live region, taking urgency and frequency into account.

## Example

**Before:** After filtering, only the number of records found changes.

**After:** A polite status message announces the number.

## Exceptions and false positives

Not every DOM update is a status message. Do not make whole pages aria-live, and do not use alert for every minor update.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. For this criterion it is especially important to compare the programmatic data with the actual presentation.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 4.1.3, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Trigger a search result, a save, an error and progress; determine whether the message is a status message; check that it is announced without moving focus.
