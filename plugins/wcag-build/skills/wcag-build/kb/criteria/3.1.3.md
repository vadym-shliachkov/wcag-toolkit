# 3.1.3 Unusual Words

WCAG 2.2 · Level **AAA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

Idioms, jargon, and words used in an unusual or restricted way; AAA.

## What is required

Provide a mechanism for identifying the specific definition.

## How to test

1. Find terms and idioms.
2. Check the definitions and whether the user can reach them.

**Expected result:** Provide a mechanism for identifying the specific definition. All applicable states and normative exceptions have been checked.

**Fails when:** A specialized term is used without an available explanation.

## How to fix

Add a definition nearby, a link to a glossary, or another mechanism.

## Example

**Before:** An instruction uses "stratification" without explanation.

**After:** The term is linked to a clear definition.

## Exceptions and false positives

Not every long word is automatically unusual; the meaning is judged for the target audience and the context.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 3.1.3, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Find terms and idioms; check the definitions and whether the user can reach them.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
