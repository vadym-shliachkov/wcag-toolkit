# 2.4.5 Multiple Ways

WCAG 2.2 · Level **AA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

The page is part of a set of web pages.

## What is required

Provide more than one way to locate the page within the set.

## How to test

1. List the available ways: navigation, search, site map, table of contents.
2. Check that the target page can actually be found.

**Expected result:** Provide more than one way to locate the page within the set. All applicable states and normative exceptions have been checked.

**Fails when:** A page in the set is reachable through only one path, with no alternative.

## How to fix

Add a working search, site map or other additional means.

## Example

**Before:** The needed instructions can be found only in a deep menu.

**After:** They can also be found through search.

## Exceptions and false positives

Pages that are the result of, or a step in, a process are exempt. Two visual instances of the same menu are not necessarily two ways.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 2.4.5, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: List the available ways: navigation, search, site map, table of contents; check that the target page can actually be found.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
