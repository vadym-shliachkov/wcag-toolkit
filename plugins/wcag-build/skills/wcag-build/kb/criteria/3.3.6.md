# 3.3.6 Error Prevention (All)

WCAG 2.2 · Level **AAA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

Submitting user information; AAA.

## What is required

Provide reversibility, checking with correction, or review/confirmation/correction before finalizing.

## How to test

1. Check submissions outside the narrow scope of 3.3.4.
2. Confirm that one of the mechanisms is present.

**Expected result:** Provide reversibility, checking with correction, or review/confirmation/correction before finalizing. All applicable states and normative exceptions have been checked.

**Fails when:** Data is submitted before it can be reviewed and corrected; there is also no reversibility and no checking with correction.

## How to fix

Add a preview with correction, or reversibility.

## Example

**Before:** A note is submitted automatically before the input can be reviewed and corrected; there is no checking and no undo.

**After:** Before submission a review is shown, with a way back to editing.

## Exceptions and false positives

The scope is wider than 3.3.4; do not carry this AAA requirement over to all forms when evaluating AA. A separate preview screen is not required: the ability to review/correct input before explicit confirmation can satisfy the Confirmed branch.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 3.3.6, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Check submissions outside the narrow scope of 3.3.4; confirm that one of the mechanisms is present.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
