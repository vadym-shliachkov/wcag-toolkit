# 3.2.6 Consistent Help

WCAG 2.2 · Level **A**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

At least one of the listed help mechanisms is repeated across a set of web pages.

## What is required

Human contact details, a human contact mechanism, a self-help option or a fully automated contact mechanism occur in the same order relative to other page content, except for changes initiated by the user.

## How to test

1. Find the repeated help mechanisms.
2. Compare their order on the pages at the same size and orientation.
3. Compare the sequence in the serialized page, not only the coordinates.

**Expected result:** Human contact details, a human contact mechanism, a self-help option or a fully automated contact mechanism occur in the same order relative to other page content, except for changes initiated by the user. All applicable states and normative exceptions have been checked.

**Fails when:** The same help mechanism moves arbitrarily relative to the other blocks.

## How to fix

Use a stable placement for help.

## Example

**Before:** "Help" appears sometimes before the form, sometimes between the fields, sometimes after the footer.

**After:** It always follows the main content.

## Exceptions and false positives

This does not require help to be created if there is none, or to be shown on every page. Changes caused by user settings and responsive modes are assessed according to the normative notes.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 3.2.6, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Find the repeated help mechanisms; compare their order on the pages at the same size and orientation; compare the sequence in the serialized page, not only the coordinates.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
