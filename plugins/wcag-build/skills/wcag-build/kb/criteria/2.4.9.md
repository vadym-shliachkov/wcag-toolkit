# 2.4.9 Link Purpose (Link Only)

WCAG 2.2 · Level **AAA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

Links; AAA.

## What is required

Provide a mechanism that allows the purpose to be identified from the link text alone.

## How to test

1. Read individual links without the surrounding paragraph.
2. Check the mechanism for expanded names.

**Expected result:** Provide a mechanism that allows the purpose to be identified from the link text alone. All applicable states and normative exceptions have been checked.

**Fails when:** A list of links contains several indistinguishable "Learn more" links.

## How to fix

Make the name self-sufficient, or provide a mechanism that makes the link text more specific.

## Example

**Before:** Three links are called "Read".

**After:** "Read the renewal rules", "Read the registration rules", "Read the delivery terms".

## Exceptions and false positives

Ambiguity to users in general is an exception. At AA, programmatic context under 2.4.4 is acceptable.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 2.4.9, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Read individual links without the surrounding paragraph; check the mechanism for expanded names.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
