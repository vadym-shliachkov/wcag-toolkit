# 1.4.1 Use of Color

WCAG 2.2 · Level **A**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

Color conveys information, distinguishes elements, or indicates an action or state.

## What is required

Convey the same information by an additional visual means.

## How to test

1. Check errors, links, charts and states.
2. Remove the color differences mentally or with a tool.
3. Find text, shape or pattern.

**Expected result:** Convey the same information by an additional visual means. All applicable states and normative exceptions have been checked.

**Fails when:** Errors are marked only by a red border without any other visual cue.

## How to fix

Add error text, a series label, a symbol or a distinct pattern.

## Example

**Before:** Available dates are marked only in green.

**After:** The cells contain the word "Available".

## Exceptions and false positives

A programmatic announcement of state may not be enough for sighted users who do not perceive color. Contrast and color are separate checks.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 1.4.1, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Check errors, links, charts and states; remove the color differences mentally or with a tool; find text, shape or pattern.
