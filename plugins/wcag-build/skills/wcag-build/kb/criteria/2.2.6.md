# 2.2.6 Timeouts

WCAG 2.2 · Level **AAA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

User inactivity could cause data loss; AAA.

## What is required

Tell users how long a period of inactivity causes data loss, unless the data is preserved for more than 20 hours with no user activity.

## How to test

1. Before starting input, find the warning.
2. Check the stated duration against what is actually preserved.

**Expected result:** Tell users how long a period of inactivity causes data loss, unless the data is preserved for more than 20 hours with no user activity. All applicable states and normative exceptions have been checked.

**Fails when:** A form silently deletes input after 15 minutes of inactivity.

## How to fix

State the duration in advance, or preserve the data for more than 20 hours.

## Example

**Before:** A draft disappears after a quarter of an hour.

**After:** Before input, the inactivity time and a way to save are stated.

## Exceptions and false positives

Do not confuse this with the warning, seconds before an imminent sign-out, under 2.2.1; what matters is knowing the duration of inactivity that leads to data loss.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 2.2.6, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Before starting input, find the warning; check the stated duration against what is actually preserved.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
