# 1.3.4 Orientation

WCAG 2.2 · Level **AA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

An interface on devices whose orientation can change.

## What is required

Do not restrict the display and operation to a single orientation unless that orientation is essential to the function.

## How to test

1. Rotate the device both ways.
2. Check access to the content and operations.
3. Rule out a system orientation lock.

**Expected result:** Do not restrict the display and operation to a single orientation unless that orientation is essential to the function. All applicable states and normative exceptions have been checked.

**Fails when:** A form does not let the user continue in landscape orientation although there is no functional need for this.

## How to fix

Remove the lock and adapt the layout.

## Example

**Before:** An observation log requires the device to be rotated to portrait.

**After:** Input works in both orientations.

## Exceptions and false positives

A restriction that is essential to the function is allowed, for example a realistic layout of a musical instrument; a design preference does not make it essential.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 1.3.4, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Rotate the device both ways; check access to the content and operations; rule out a system orientation lock.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
