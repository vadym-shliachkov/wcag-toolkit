# 3.2.4 Consistent Identification

WCAG 2.2 · Level **AA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

Components that have the same functionality within a set of web pages.

## What is required

The same functionality is identified consistently.

## How to test

1. Compare the names, text alternatives and recognizable identifiers of the same functions.

**Expected result:** The same functionality is identified consistently. All applicable states and normative exceptions have been checked.

**Fails when:** The same search button has unrelated identification in different sections.

## How to fix

Unify the names and semantics of identical functions.

## Example

**Before:** The same function is named "Find" and "Run" with no contextual reason.

**After:** "Find" is used consistently.

## Exceptions and false positives

Different functions can have different identification; contextual clarifications are acceptable. Do not require every string to match literally.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 3.2.4, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Compare the names, text alternatives and recognizable identifiers of the same functions.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
