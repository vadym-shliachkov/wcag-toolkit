# 2.2.4 Interruptions

WCAG 2.2 · Level **AAA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

Content creates interruptions; AAA.

## What is required

Allow the user to postpone or suppress interruptions, except those involving an emergency.

## How to test

1. Turn on the no-interruptions mode.
2. Check notifications and the return to the task.

**Expected result:** Allow the user to postpone or suppress interruptions, except those involving an emergency. All applicable states and normative exceptions have been checked.

**Fails when:** A non-urgent notification keeps interrupting input and cannot be postponed.

## How to fix

Add settings for deferred display and a no-interruptions mode.

## Example

**Before:** Form-filling tips open a dialog every 30 seconds.

**After:** The tips are collected in a separate section.

## Exceptions and false positives

Emergency messages are allowed; not every page update is an interruption, so describe the effect.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 2.2.4, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Turn on the no-interruptions mode; check notifications and the return to the task.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
