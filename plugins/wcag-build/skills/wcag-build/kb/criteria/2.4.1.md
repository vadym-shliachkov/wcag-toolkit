# 2.4.1 Bypass Blocks

WCAG 2.2 · Level **A**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

Blocks are repeated on multiple pages.

## What is required

Provide a mechanism to bypass blocks of content that are repeated.

## How to test

1. Start navigating from the top of the page.
2. Check the skip link or another working bypass mechanism.
3. Confirm that the intended region is reached.

**Expected result:** Provide a mechanism to bypass blocks of content that are repeated. All applicable states and normative exceptions have been checked.

**Fails when:** Before the content of every page, a large repeated block must be passed through with no way to bypass it.

## How to fix

Add a working link to the main content, or another supported mechanism.

## Example

**Before:** Reaching the text requires passing 45 menu links.

**After:** The first link moves to main, and further navigation continues from there.

## Exceptions and false positives

A skip link specifically is not the only acceptable solution. The absence of main does not by itself prove a failure.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 2.4.1, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Start navigating from the top of the page; check the skip link or another working bypass mechanism; confirm that the intended region is reached.
