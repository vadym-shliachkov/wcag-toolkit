# 2.5.3 Label in Name

WCAG 2.2 · Level **A**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

A component has a visible label with text or an image of text.

## What is required

The accessible name contains the text of the visible label.

## How to test

1. Compare the displayed label with the computed accessible name.
2. Check the dynamic states and a voice command.

**Expected result:** The accessible name contains the text of the visible label. All applicable states and normative exceptions have been checked.

**Fails when:** A visible "Sign up" button has the name "Submit application".

## How to fix

Include the visible text in the accessible name; preferably start the name with it.

## Example

**Before:** A "Renew" button has aria-label "Update due date".

**After:** The name is "Renew loan period".

## Exceptions and false positives

Do not require the names to be identical. Assess the human-readable label text, not a mechanical match of every decorative character; icons without text are a different case.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. For this criterion it is especially important to compare the programmatic data with the actual presentation.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 2.5.3, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Compare the displayed label with the computed accessible name; check the dynamic states and a voice command.
