# 2.4.2 Page Titled

WCAG 2.2 · Level **A**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

Every web page, including single-page application routes.

## What is required

The page title describes its topic or purpose.

## How to test

1. Read the title.
2. Change the route.
3. Compare it with the purpose of the current page.

**Expected result:** The page title describes its topic or purpose. All applicable states and normative exceptions have been checked.

**Fails when:** Different pages have the meaningless title "Document".

## How to fix

Set a clear, distinguishing title and update it on routing.

## Example

**Before:** The browser tab of the change-password page is called "Page".

**After:** "Change password — My account".

## Exceptions and false positives

Absolute uniqueness of every title, out of context, is not required; an h1 does not replace the page title.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. For this criterion it is especially important to compare the programmatic data with the actual presentation.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 2.4.2, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Read the title; change the route; compare it with the purpose of the current page.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
