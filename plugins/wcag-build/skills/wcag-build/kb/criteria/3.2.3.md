# 3.2.3 Consistent Navigation

WCAG 2.2 · Level **AA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

Navigation mechanisms are repeated across a set of web pages.

## What is required

Their relative order is the same, except for changes initiated by the user.

## How to test

1. Compare the same navigation mechanisms on several pages and in the same responsive mode.

**Expected result:** Their relative order is the same, except for changes initiated by the user. All applicable states and normative exceptions have been checked.

**Fails when:** The same menu arbitrarily changes the order of its items between pages.

## How to fix

Keep a stable relative order.

## Example

**Before:** "Catalog" and "Rules" swap places in different sections.

**After:** Their order is stable.

## Exceptions and false positives

The same absolute position and an identical set of items are not required; changes made by the user are allowed.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 3.2.3, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Compare the same navigation mechanisms on several pages and in the same responsive mode.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
