# 3.2.2 On Input

WCAG 2.2 · Level **A**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

Changing the setting of a component, for example selecting an option.

## What is required

Do not change the context automatically unless the user has been advised of it before using the component.

## How to test

1. Change checkboxes, selects and other values.
2. Check for a warning before the action and the actual consequences.

**Expected result:** Do not change the context automatically unless the user has been advised of it before using the component. All applicable states and normative exceptions have been checked.

**Fails when:** Selecting a value immediately takes the user to another page without warning.

## How to fix

Add an explicit apply button or explain the change of context in advance.

## Example

**Before:** Selecting a region item immediately takes the user away from the page.

**After:** The region is applied with a "Show" button.

## Exceptions and false positives

Updating results without a change of context is not automatically a failure; assess status messages separately under 4.1.3.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 3.2.2, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Change checkboxes, selects and other values; check for a warning before the action and the actual consequences.

## Code patterns

The scenario is given above. Code alone is not enough to test media, processes and semantics.
