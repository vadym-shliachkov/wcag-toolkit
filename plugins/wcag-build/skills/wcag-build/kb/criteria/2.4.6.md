# 2.4.6 Headings and Labels

WCAG 2.2 · Level **AA**

A practical summary in our own words; the exact obligations are set by the normative text and its definitions.

## Applicability

Headings and labels that are present.

## What is required

They describe the topic or purpose.

## How to test

1. Read the headings and labels in context.
2. Compare them with the purpose of the section and the field.

**Expected result:** They describe the topic or purpose. All applicable states and normative exceptions have been checked.

**Fails when:** A start-date field is labeled "Value", which does not describe the expected input.

## How to fix

Name the subject of each section and the purpose of each field.

## Example

**Before:** A section about returning books is titled "Other".

**After:** "Book return deadlines".

## Exceptions and false positives

The criterion assesses how descriptive the existing headings and labels are. Do not turn it into a requirement for an h1 or for a separate heading on every container.

## Automation and evidence

A tool can collect candidates and measurements; the verdict depends on applicability, content, exceptions and observed behavior. The absence of an automated signal is not a pass. The main conclusion requires a person to carry out the scenario, or an observed interactive run; a static DOM alone is not enough.

- URL/route, interface state, date, sign-in method and the steps tested.
- Viewport in CSS px, zoom level, input method, user agent, and assistive technologies if used.
- The specific element/media segment/process step, reproducible observations and the actual result.
- The normative condition of 2.4.6, the exceptions checked, and an explanation of the barrier to the user.
- For this test, record: Read the headings and labels in context; compare them with the purpose of the section and the field.
